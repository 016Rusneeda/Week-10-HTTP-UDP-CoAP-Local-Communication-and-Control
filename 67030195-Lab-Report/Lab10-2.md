## 4. บันทึกผลการทดลองและคำถามท้ายการทดลอง 
1. นำผลการวัดค่า RTT Latency ของ UDP ในกิจกรรมที่ 10-2.5 มาเปรียบเทียบกับความหน่วงเวลาของ HTTP RESTful ในใบงาน 10.1 และวิเคราะห์ความแตกต่าง
   
   **ตอบ** ความหน่วงเวลาของ UDP จะต่ำกว่า HTTP RESTful อย่างเห็นได้ชัด UDP มักอยู่ในระดับไม่เกิน 10-20 ms ในขณะที่ HTTP มักจะสูงกว่าหลายเท่าตัว
   **วิเคราะห์ความแตกต่าง**
    - HTTP ทำงานบนสแตก TCP มีความหน่วงสะสมสูง เนื่องจากต้องมีการสร้างการเชื่อมต่อ (3-Way Handshake) ก่อนส่งข้อมูลทุกครั้ง มีขนาด HTTP Header ที่ใหญ่ และบอร์ดต้องเสียเวลาประมวลผลสตริง JSON
    - UDP เป็นโปรโตคอลแบบไร้การเชื่อมต่อไม่ต้อง Handshake ขนาด Header เล็กมาก (เพียง 8 ไบต์) เมื่อเรียกคำสั่ง sendto() บอร์ดจะยิงข้อมูลออกสู่เครือข่ายทันที ทำให้ประหยัดเวลาและประมวลผลได้เร็วกว่า
      
2. รันสคริปต์ `udp_listener.py` เป็นเวลา 1 นาที จงบันทึกค่าและคำนวณอัตราการสูญหายของแพ็กเก็ต (Packet Loss Rate) พร้อมวิเคราะห์สาเหตุที่ทำให้เกิดการสูญหายบนเครือข่าย Wi-Fi
   **ตอบ** 
   **ผลการทดลอง**
    - รับข้อมูลได้จริง 855 แพ็กเก็ต
    - Lost 116 แพ็กเก็ต
    - อัตราการสูญหาย (Packet Loss Rate): 11.95%
  
    **วิเคราะห์สาเหตุการสูญหายบน Wi-Fi**
    - โปรโตคอล UDP ส่งข้อมูลแล้วทิ้งเลย (Fire-and-forget) ไม่มีการขอส่งใหม่ (No Retransmission) เหมือน TCP
    - มักจะส่งแพ็กเก็ต Broadcast ด้วยความเร็วต่ำสุด และไม่มีการยืนยันการรับแพ็กเก็ตในระดับฮาร์ดแวร์ No MAC-level ACK ทำให้ถ้ามีสัญญาณชนกันกลางอากาศ แพ็กเก็ตจะหายไปทันที
    - คลื่น 2.4GHz มีข้อจำกัดเรื่องช่องสัญญาณที่ทับซ้อนกัน หากมีอุปกรณ์อื่นใช้งานเครือข่ายพร้อมกันจำนวนมาก จะทำให้เกิด Packet Drop สูง
      
3. อธิบายข้อดีและข้อจำกัดของการใช้ `255.255.255.255` (UDP Broadcast) ในระบบ IoT และในสถานการณ์ใดที่ควรเปลี่ยนไปใช้ **UDP Multicast** หรือ **Unicast** แทน?

   **ตอบ**
    - **ข้อดี** อุปกรณ์ที่ส่งข้อมูลไม่จำเป็นต้องรู้หมายเลข IP ของผู้รับ ส่งแพ็กเก็ตเดียวแต่อุปกรณ์ทุกตัวในเครือข่ายสามารถรับข้อมูลได้พร้อมกัน เหมาะมากสำหรับระบบค้นหาอุปกรณ์
    - **ข้อจำกัด** เป็นการสร้างขยะบนเครือข่าย ทำให้อุปกรณ์ทุกตัวในวง LAN ต้องถูกขัดจังหวะเพื่อมาอ่านแพ็กเก็ตนี้ ทำให้สิ้นเปลืองแบตเตอรี่และแบนด์วิดท์ อีกทั้งเราเตอร์ส่วนใหญ่จะบล็อกแพ็กเก็ต Broadcast ไม่ให้ข้ามวง LAN ได้

    - ควรใช้ UDP Multicast เมื่อต้องการส่งข้อมูลให้กับกลุ่มเป้าหมายหลายตัว แต่ไม่ใช่ทุกคน เช่น สั่งงานกลุ่มไฟอัจฉริยะเฉพาะโซนห้องรับแขก โดยไม่ไปรบกวนคอมพิวเตอร์หรือโทรศัพท์เครื่องอื่นในบ้าน และยังสามารถตั้งค่าให้ส่งข้ามวง LAN ได้

    - ควรใช้ UDP Unicast เมื่อต้องการส่งข้อมูล Telemetry ความถี่สูงไปยังเซิร์ฟเวอร์หรือคอมพิวเตอร์เป้าหมายเพียงตัวเดียว เพื่อลดภาระการกระจายทราฟฟิกของเครือข่าย และให้เราเตอร์สามารถให้ความสำคัญกับแพ็กเก็ตได้ดีกว่าเดิม
